# riskwatch · 云端部署指南

编制：2026-11-26 · 目标：**电脑关机、微信不登录、人不在场，风险日报照常送达**

- 定时任务：北京时间 **08:30 / 18:00** 各一次（UTC 00:30 / 10:00）
- 覆盖：**12 个权威源**（监管机构 + 海关总署 + 人民日报 / 新华网 / 央视网）
- 特色栏目：**蛇口海运 · 保税区专题（货运 / 旅检）**，跨源汇总海运货运、旅检、保税区与蛇口 / 前海片区案件
- 投递：企业微信群（摘要 + `.md` + `.docx` 群文件）＋ QQ 邮箱（HTML 正文 + 附件）
- 归档：每天两份日报自动 commit 到新仓库 `reports/`
- 形态：**新建独立 Private 仓库**，与现有 `hotpush` 热搜任务互不干扰

| 你做什么             | 我做了什么                           |

**你全程不需要装 Python、不需要开电脑、不需要让微信保持登录。**

## 一、前置清单

- [ ] 一个 GitHub 账号（沿用你 `hotpush` 那个账号即可）
- [ ] 企业微信「**消息推送**」机器人的完整 Webhook 地址（形如  
  `https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=...`）  
  —— **可以直接复用热搜项目那个**，两个仓库往同一个群发也行
- [ ] 一个开通了 **IMAP/SMTP 服务**的 QQ 邮箱 + 16 位授权码
- [ ] 收件邮箱地址（可以就是发件邮箱自己）

> ⚠️ Secret **不跨仓库**。即使在 `hotpush` 仓库填过 `WECOM_WEBHOOK`，  
> 新仓库里也要**重新填一次**。

## 二、第 1 步：新建空仓库

1. GitHub → 右上角 `+` → `New repository`
2. **Repository name**：例如 `riskwatch`（随意）
3. 选 **Private**
4. **不要勾** `Add a README file` / `.gitignore` / license，保持完全空白
5. 点 `Create repository`

> 这个仓库和 `hotpush` 是**两个独立仓库**。不要把这个项目的文件传到热搜那个仓库里。

## 三、第 2 步：上传 4 个文件

本地 `riskwatch/` 目录**就是新仓库的根目录**，上传后应该是这个结构：

```
仓库根/
├── .github/
│   └── workflows/
│       └── riskwatch.yml        ← 定时任务
├── riskwatch.py                  ← 主程序
├── config.cloud.json             ← 云端配置（无密钥）
└── .gitignore                    ← 防误传
```

`README.md`、`云端部署指南.md`、`样例日报预览*.docx` 传不传都行，不影响运行  
（样例预览是用本地样本生成的排版示例，可先点开看报告长什么样）。  
`_fixtures/` 是本地离线自检样本，已被 `.gitignore` 排除，**不要上传**。  
`reports/` 是运行时自动生成的归档目录，**不用预先创建**。

**方式 A（网页拖拽，不用装软件）**

`Code` → `Add file` → `Upload files` → 把 `riskwatch.py`、`config.cloud.json`、`.gitignore` 拖进去 → `Commit changes`。  
`.github` 是隐藏目录，Windows 拖拽容易漏，**建议单独用方式 B 建工作流文件**。

> ⚠️ **方式 A 和方式 B 都要做**。只做 B 会得到  
> `python: can't open file 'riskwatch.py'`（出口代码 2）。  
> 拖文件时**只拖文件本身**，别把整个本地 `riskwatch/` 文件夹拖进去 —— 那样路径会变成  
> `riskwatch/riskwatch.py`，runner 在仓库根目录照样找不到。  
> 上传完到 `Code` 页确认：根目录**直接**能看到 `riskwatch.py`、`config.cloud.json`、`.github/`。  
> 工作流已内置「检查必需文件」步骤，缺哪个会直接点名。

**方式 B（建工作流文件，最稳）**

`Code` → `Add file` → `Create new file` → 文件名框里**直接填**：

```
.github/workflows/riskwatch.yml
```

（带斜杠，GitHub 会自动建目录）→ 把**附录 A** 的 YAML 全文粘进去 → `Commit directly to the main branch` → `Commit new file`。

**上传后自检**：点仓库顶部 `Code`，应能看到 `riskwatch.py`、`config.cloud.json` 和 `.github` 文件夹；  
再点 `Actions`，左侧应出现「**风险信息日报**」而不是「开始使用 GitHub Actions」引导页。  
如果还是引导页，说明 `.github/workflows/riskwatch.yml` 没进默认分支 `main`，检查目录层级与分支下拉。

## 四、第 3 步：企业微信 Webhook

如果你要**复用热搜项目那个群**，把当时那条 Webhook 原样用即可，不用改群。  
找不到地址的话：

> 企业微信**电脑端** → 打开群 → 右上角 `···` → **「消息推送」**（旧版叫「群机器人」）  
> → 点开机器人 → 右上角编辑（铅笔）→ 「Webhook 地址」→ 复制

认准一个特征：**必须是 `https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=` 开头的完整网址**。

- 如果拿到的是 **Bot ID + Secret 两串**，那是「智能机器人」，不是「消息推送」，本方案用不了；  
  回到群里找「消息推送」入口重新添加一个。
- 只有创建人/群主/管理员能看 Webhook；看不到就删掉重建一次，创建弹窗里会直接给「复制地址」。
- 企业微信群机器人**没有加签 / 关键词 / IP 白名单**（那是钉钉的），别照钉钉教程改代码。

## 五、第 4 步：拿 QQ 邮箱 16 位授权码

1. 浏览器登录 **QQ 邮箱网页版** → `设置` → `账号`
2. 找到 `POP3/IMAP/SMTP/Exchange/CardDAV/CalDAV 服务`
3. 开启 **「IMAP/SMTP 服务」** → 按提示发短信验证
4. 页面给出一串 **16 位授权码**，**只显示一次，当场复制**

要点：

- 授权码**不是 QQ 密码**，也不是邮箱登录密码；第三方客户端只能用授权码
- 官方那份 IMAP/SMTP、POP3/SMTP 设置说明里，**本项目只用到「发送邮件服务器」一行**：  
  `imap.qq.com:993`（IMAP）和 `pop.qq.com:995`（POP3）是**收件**用的，脚本只发不收，  
  不用配置、也不要填进 GitHub
- **465 = SSL 直连**、**587 = STARTTLS（先明文连接再升级 TLS）**，握手方式不同，不能混用。  
  脚本两种都支持：`QQ_SMTP_PORT` 不填默认走 `465`；填 `587` 自动走 STARTTLS。  
  误填 993 / 995 会给出明确报错提示
- 个人版 SMTP 是 `smtp.qq.com:465`（SSL）；企业版腾讯企业邮是 `smtp.exmail.qq.com`，  
  如果用企业邮，加仓库 Variable `QQ_SMTP_HOST=smtp.exmail.qq.com`、`QQ_SMTP_PORT=465`
- 授权码等同密码，**不要贴聊天、不要提交进仓库**

## 六、第 5 步：填 4 个 Secret

新仓库 → `Settings` → 左侧 `Secrets and variables` → `Actions` → `New repository secret`，  
逐个新建（**名字必须完全一致，全大写**）：

| Name            | 值                                                                         | 必填      |
| --------------- | ------------------------------------------------------------------------- | ------- |
| `WECOM_WEBHOOK` | 第 3 步那条完整 `https://...key=...` 网址                                         | ✅       |
| `QQ_SMTP_USER`  | 发件邮箱**完整地址**，如 `123456789@qq.com`                                         | ✅（要发邮件） |
| `QQ_SMTP_CODE`  | 第 4 步的 16 位授权码                                                            | ✅（要发邮件） |
| `RISK_MAIL_TO`  | 收件人，多个用英文逗号分隔，如 `a@qq.com,b@163.com`；**填 Secret 或 Variable 都行**（工作流已兼容两者） | ✅（要发邮件） |

**可选**（不填也能跑，报告为纯统计版）：

| Name                            | 类型       | 说明                                                                                      |
| ------------------------------- | -------- | --------------------------------------------------------------------------------------- |
| `LLM_API_KEY`                   | Secret   | OpenAI 兼容接口密钥；填了日报第十节自动追加 AI 趋势研判                                                       |
| `LLM_BASE_URL`                  | Variable | 默认 `https://api.deepseek.com/v1`；智谱/通义/OpenAI 换这个值                                      |
| `LLM_MODEL`                     | Variable | 默认 `deepseek-chat`                                                                      |
| `QQ_SMTP_HOST` / `QQ_SMTP_PORT` | Variable | 换服务商或换端口时用；**不填回落 `smtp.qq.com:465`（SSL）**，填 `QQ_SMTP_PORT=587` 自动走 STARTTLS；工作流已传入运行环境 |

> GitHub 会把 Secret 在日志里显示成 `***`；脚本另外对所有 URL 做了 `key=***` 脱敏。  
> **不要把这四条发给我或贴到聊天里。**

## 八、定时怎么生效、怎么改时间

定时**已经写在 `.github/workflows/riskwatch.yml` 里**，手动 `Run workflow` 只是验证按钮，  
不是「启动定时器」的开关：

```yaml
on:
  schedule:
    - cron: '30 0,10 * * *'   # UTC 00:30 / 10:00 = 北京时间 08:30 / 18:00
```

生效条件（新建仓库默认都满足）：工作流在默认分支 `main`；`Settings → Actions → General` 里 Actions 开启。  
**每天两次的日报归档提交本身就会保持仓库活跃**，不会触发 GitHub「60 天无活动自动停用定时任务」。

在 `Actions` 页看运行记录的触发标记：`Schedule` = 定时触发，`workflow_dispatch` = 手动触发。  
整点前后 GitHub 排队，晚几分钟属正常。

**改时间**：只改 yml 里那一行 cron，**北京时间减 8 小时换算成 UTC**，改完 commit 即生效：

| 想要                  | cron                |
| ------------------- | ------------------- |
| 当前：每天 08:30 / 18:00 | `'30 0,10 * * *'`   |
| 每天 09:00 / 18:00    | `'0 1,10 * * *'`    |
| 每天一次 08:30          | `'30 0 * * *'`      |
| 只工作日 08:30 / 18:00  | `'30 0,10 * * 1-5'` |
| 避开整点排队              | `'37 0,10 * * *'`   |

⚠️ 若选北京时间 00:00–07:59，UTC 会落在**前一天**，写星期字段时要往前错一天。

改完记得**同步本指南附录 A 的全文**，否则以后照附录新建文件会把旧 cron 复制回去。

## 九、数据源、「蛇口专题」与「香港海关重点」

### 9.1 特别栏目：蛇口海运 · 保税区专题（货运 / 旅检）

按你的业务特点（**蛇口海关海运口岸 + 前海蛇口自贸片区 / 保税区**）新增，位于报告  
**第三节**、邮件第三节、群摘要一行，Word 同步。四个维度：

| 维度               | 典型命中词                               | 主要由谁喂数据                       |
| ---------------- | ----------------------------------- | ----------------------------- |
| 货运渠道             | 集装箱、货柜、海运、舱单、报关、夹藏、伪报、冻品、固体废物、码头、查验 | 香港海关货运案件、海关总署要闻、央视网 / 人民网走私报道 |
| 旅检渠道             | 旅检、旅客、行李、水客、免税、携带、出入境、代购、红色通道       | 香港海关机场旅客案件（占大头）、人民网「旅检」检索     |
| 保税区与特殊监管区域       | 保税、综合保税区、账册、加工贸易、二线出区、跨境电商、围网卡口     | 人民网「保税区」检索、市场监管新规、总署通关改革      |
| 蛇口 · 前海 · 深圳西部港区 | 蛇口、赤湾、妈湾、前海、深圳海关、大铲湾、盐田、深圳湾         | 海关总署首页要闻、央媒深圳报道               |

规则要点：

- **跨源镜像**：命中条目在第四至第八节的原分类里仍然保留，第三节只是按渠道重列一次，  
  **不重复计入总数**；一条可命中多个维度，正文按第一命中维度归组，全部维度写在  
  「专题：货运、旅检…」标签里。
- **保底收录**：命中专题且非党建 / 慰问类噪声的条目，即使相关性分数低于 `min_score`  
  也收录，保证「货运和旅检的相关案件都放进去」。
- **可调整**：四组关键词在 `riskwatch.py` 的 `LOCAL_GROUPS`，按口岸实际业务口径增删即可；  
  改完用 `python riskwatch.py --offline --dry-run` 回归。

> 本期专题为空是**正常**的：说明时间窗内各源没有命中这些词的公开标题，不代表没有业务动态。  
> 想放宽就调对应源的 `lookback`（天）或往 `LOCAL_GROUPS` 里加词。

### 9.2 重点源：香港海关 · 新闻公报

按你的要求单独成章（报告**第四节**、邮件第四节），待遇与其它源不同：

| 项目    | 其它源          | 香港海关新闻公报                |
| ----- | ------------ | ----------------------- |
| 抓取条数  | 15–45 条      | **30 条**（列表页只解析最新 60 条） |
| 相关性过滤 | 阈值 1–2，不相关剔除 | **不过滤**（栏目本身即执法公报）      |
| 章节    | 按四类合并        | **独立第四章**，再按 7 类案件细分    |
| 摘要    | 汇总一行         | **单独一行统计条数**            |

> 第三节专题会**再列一次**其中属货运 / 旅检的公报（如「机场侦破入境旅客贩毒案」  
> 归旅检、「货柜夹藏走私冻品」归货运），两处是同一条，不是重复计数。

案件子类型：毒品与贩毒 / 食药与受管制物品 / 走私与未完税烟草 / 冒牌货与知识产权 /  
洗钱与贵金属交易 / 濒危物种与生态 / 其他执法动态。  
每条还自动提取涉案金额与数量（如「约七百万元」「41批次」）作为数字线索。

| **央视网 · 新闻检索**        | `search.cctv.com/search.php?...&sort=date`                        | 取 `<span lanmu1="真实URL">` 里的标题，URL 自带日期                    | 30 天 |

人民网检索的 6 个关键词：`走私`、`海关查获`、`食品安全`、`保税区`、`旅检`、`市场监管`。  
低频词（如「旅检」）近 7 天常无新稿，属正常；想放宽就把该源 `lookback` 调到 14–30 天。

### 9.4 为什么一开始没放人民日报 / 新华网，现在怎么补上的

这是你问的问题，如实说明：

1. **最初只选「监管机构一手发布」的站**：政府栏目页有稳定可解析的列表 / RSS / JSON  
   API，零依赖就能解析；而人民日报、新华网是综合新闻门户，属于**报道**而非**通报**，  
   容易与监管源同题重复。
2. **官媒 RSS 大面积失修**：实测人民网 `rss/politics.xml` 虽然返回 200，但内容停在  
   2025-06-05，`rss/legal.xml` 返回的是教育频道旧内容；新华网 RSS 直接 404。  
   拿它当每日源只会抓回一年多前的旧稿。
3. **栏目页多为 JS 动态渲染**：新华网法治页里混着 2022 年的模板存档链接，  
   央视网首页链接需要清洗注释才能取到真实地址；直接按 `<a>` 全量抓会把旧稿当新闻。
4. **Google News 聚合在本机被拦**：原先只放了一个默认关闭的 `gnews_food` 作补充，  
   本机测试超时，所以没敢默认开启。

这次逐个实测后换成各家**能稳定返回结构化数据的官方入口**：

- 人民网改用**官方检索接口**（HTTP 明文 POST，`sortType=0` 按发布时间倒序，  
  `startTime` 直接限定时间窗），按业务关键词定向检索，实测能拿到 2026-11-26 当天稿件；
- 新华网 / 央视网改用**静态栏目页 + 官方检索页**，并只取 URL 内嵌日期的稿件；
- 顺带补上**海关总署首页**（对蛇口海关最贴身的一手源，能看到「深圳海关」相关要闻）。

央媒条目在报告里明确标为**报道线索**，同题多源会标「同题来源」，跨源按「标题 + 日期」  
去重，定性一律以官方原文为准。**新增源不需要改 workflow**，只改 `SOURCES` 和  
`config.cloud.json` 的 `sources` 数组即可。

**繁体处理**：香港政府新闻网只有繁体 RSS，脚本内置常见字繁→简归一化**仅用于关键词匹配**，  
显示与链接一律保留原文，不改写来源标题。


### 9.5 海关业务聚焦（默认开启）

按你的要求「**除了食安信息的，新闻侧重货运旅检这些与蛇口海关相关、海关业务相关**」，
在收录阶段加了一层筛选，位于**时间窗之后、相关性打分之前**：

| 条目 | 是否保留 | 依据 |
| --- | --- | --- |
| 食安专用源（`samr_food` / `cfs_alert` / `cfs_press`） | **全部保留** | 不受业务聚焦影响 |
| 标题含食安词（食品、抽检、不合格、致敏、含菌量、餐饮、奶粉…） | **保留** | `FOOD_KEYS` 豁免 |
| 香港海关新闻公报（重点源） | **全部保留** | 本身就是海关执法公报 |
| 命中货运 / 旅检 / 保税区渠道，或海关业务关键词 | **保留** | `CUSTOMS_BIZ_KEYS` |
| 其余（泛社会案件、泛市场监管规章、党建宣传、民生新规） | **滤除** | 与口岸业务无关 |

海关业务关键词覆盖：机构与业务（海关、缉私、口岸、通关、报关、关税、查验、检验检疫、
原产地、税则、AEO、单一窗口）、货运海运（集装箱、货柜、舱单、提单、船舶、码头、夹藏、
伪报、冻品、固体废物）、旅检（旅客、行李、水客、免税、未完税、邮轮、红色通道）、
保税区（综合保税区、账册、加工贸易、二线出区、跨境电商、围网卡口）、
案件类型（走私、查获、检获、冒牌、侵权、洗钱、贩毒、濒危物种）、
蛇口片区（蛇口、赤湾、妈湾、前海、深圳海关、大铲湾、盐田…）。

几个刻意的设计：

- **不放「侦破 / 捣破 / 判囚」这类泛执法动词**，否则「上海侦破生态环境刑事案件」会混进来；
  真正的海关案件标题通常同时含「海关 / 走私 / 查获 / 旅客 / 集装箱」等核心词。
- **不放裸「深圳」**：只凭地名会把「深圳打造放心消费集聚区」当业务新闻；
  用的是「深圳海关 / 蛇口 / 赤湾」等明确指向口岸的词。
- **专题豁免只认货运 / 旅检 / 保税区三个渠道维度**，纯地域命中不豁免。
- 党建 / 慰问 / 主题宣传类即使带业务词也先滤掉（`NOISE` 词表）。

**透明度**：报告第九节「来源完整性」表新增「聚焦滤除」列，逐源显示滤掉多少条；
今日速览、群摘要、邮件统计区给出合计。离线样本实测：**63 → 40 条，滤除 49 条，
食安 16 条与香港海关 18 条一条没少**，货运 / 旅检 / 保税区案件仍完整进入专题。

**想看全量**：把 `config.cloud.json` 的 `customs_focus.enabled` 改成 `false`；
只想保留食安豁免逻辑就留 `exempt_food: true`。改词表去 `riskwatch.py` 的
`CUSTOMS_BIZ_KEYS` / `FOOD_KEYS` / `FOOD_SOURCE_IDS`。**不用改 workflow**。

## 十一、合规边界与口径

- **不抓微信公众号正文**：微信未开放「读取任意公众号文章」的公开 API，Cookie/抓包、
  模拟登录、搜狗微信爬取都违反《微信公众平台运营规范》且 Cookie 7–30 天失效，
  撑不住每天两次无人值守。官媒公众号、香港海关公众号的内容改用**同一机构官网栏目页 +
  香港政府官方 RSS** 等同源渠道，零费用、可长期无人值守。
- **只采集公开标题、日期、链接与摘要**，不转载正文、不做二次发布；每条附原文链接，
  请以原文为准。用于个人/内部查阅。
- **央媒条目是报道线索，不是官方通报**：人民日报 / 新华网 / 央视网的内容只作补充线索，
  同题多源会标「同题来源」，跨源按「标题 + 日期」去重；定性以监管机构原文为准。
- **风险等级、案件类型、类别与专题维度由关键词规则自动判定**，属辅助线索而非官方定性，
  可能误判/漏判；报告第九节与邮件页脚均写明了这一点。
- **除食安信息外，新闻按海关业务聚焦筛选**，属内部查阅口径而非官方分类；
  食安专用源与香港海关重点源豁免，滤除条数逐源公开，可一键关闭（见 9.5 节）。
- **不碰个人微信**：不用 iPad 协议、PC Hook、模拟按键或 UI 自动化。企业微信
  「消息推送」Webhook 是官方能力，仅能单向出站到企业微信内部群。
- **密钥**：Webhook、SMTP 授权码、模型 key 只在 GitHub Secrets / 本机环境变量，
  日志统一脱敏，仓库里没有任何明文凭证。
