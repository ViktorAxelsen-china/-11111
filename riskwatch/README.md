# riskwatch · 风险信息日报

每天自动抓取公开发布的风险信息，分类分级、生成日报，投递到**企业微信群**与 **QQ 邮箱**。
GitHub Actions 云端定时，**电脑关机、微信不登录都不影响**。

> 部署操作请看 [**云端部署指南**](./云端部署指南.md)（分步、含 Secret 配置与排障）。
> 编制：2026-11-26 · 定时：北京时间 **08:30 / 18:00** 各一次

---

## 一句话原理

GitHub 的服务器在 UTC 00:30 / 10:00 临时拉起一个 Linux 容器，抓 **12 个权威源** →
按四类分组 + 风险分级 + **蛇口海运/保税区专题跨源汇总** → 生成 Markdown / Word 日报 →
发企业微信群文件与摘要、发 QQ 邮箱 HTML 正文与附件 → 日报归档到仓库 `reports/` → 容器销毁。
本机只用来改代码和看日志，**不参与运行**。

## 覆盖什么

| 章节 | 内容 | 主要来源 |
| --- | --- | --- |
| 一、今日速览 / 二、高风险预警 | 数量、等级分布、最需优先看的 3 条 | 全部来源 |
| **三、蛇口海运 · 保税区专题（货运 / 旅检）★** | 结合蛇口海关**海运口岸 + 前海蛇口自贸片区/保税区**特点单设：货运渠道、旅检渠道、保税区与特殊监管区域、蛇口·前海·深圳西部港区，四组归类、命中即汇总 | 香港海关新闻公报、海关总署、人民日报/新华网/央视网、市场监管总局等**跨源镜像** |
| 四、香港海关 · 新闻公报（**重点**） | 贩毒、走私与未完税烟草、冒牌与侵权、食药与受管制物品、洗钱、濒危物种等，按 7 类案件细分 | 香港海关官网「新闻公报」 |
| 五、食品安全与产品风险 | 抽检不合格、食物警报、致敏物警报、超标与污染物 | 市场监管总局食品抽检司、香港食安中心、央媒报道 |
| 六、重大案件与执法查获 | 侦破、查获、查处、专项行动、司法结果 | 市场监管总局要闻、香港政府新闻网·治安、央媒报道 |
| 七、监管新规与公告 | 规章、办法、条例、标准、名录、修订与生效 | 市场监管总局法规司、食安中心新闻稿 |
| 八、其他风险提示 / 九、来源完整性 / 十、AI 研判 | 兜底条目、每源抓取状态与口径、可选大模型趋势研判 | — |

**专题第三节是跨源镜像**：命中的条目在原分类（第四至第八节）里仍然保留，第三节只是
按业务渠道重新集中列一次，**不重复计入总数**。一条可同时命中多个维度，正文按第一命中
维度归组，全部命中维度显示在每条的「专题：货运、旅检…」标签里。命中专题且非党建/慰问类
噪声的条目**保底收录**，不会因相关性分数低被过滤掉。

每条都带**风险等级（高/中/低）**、原文链接、来源、日期、`🆕` 新增标记，以及自动提取的
数字线索与涉及主体。**报告只收录公开标题/日期/链接/摘要，不转载正文。**

| 人民日报 / 人民网 · 官方检索 | 内地 | 官方检索接口 POST，6 个业务关键词轮询、按时间倒序 | 7 天 |
| 新华网 · 法治频道 | 内地 | 官网栏目页（URL 自带 8 位日期） | 14 天 |
| 央视网 · 新闻检索 | 内地 | 官方检索页，按发布时间排序 | 30 天 |

**为什么之前没放央媒、现在补上**：起初只选「监管机构一手发布」的站，因为政府栏目页
有稳定可解析的列表 / RSS / JSON API，而人民日报、新华网是综合门户，官方 RSS 已停更
（实测 `people.com.cn/rss/politics.xml` 内容停在 2025-06-05）、栏目页大量是 JS 动态渲染、
且央媒是**报道**而非**通报**，容易与监管源重复。这次逐一实测后改用各家的**官方检索接口 /
静态栏目页**，并按「走私、海关查获、食品安全、保税区、旅检、市场监管」等业务关键词定向
检索，既能拿到当天稿件，又能和监管源做跨源同题去重（报告标「同题来源」）。

另有 2 个**默认关闭**的可选源：香港政府全部门公报 RSS（英文）、Google News 中文关键词聚合。
B站 / 抖音等新媒体 UP 主与公众号直连接口**已留扩展位，暂未接入**（见指南第六节）。

## 本机常用命令

```bash
python riskwatch.py --list-sources                    # 列出全部数据源与 URL
python riskwatch.py --dry-run                        # 真实抓取并预览，不发送
python riskwatch.py --offline --dry-run              # 用本地样本离线自检，不联网
python riskwatch.py --dry-run --sources hkc_press,cfs_alert   # 只跑指定源
python riskwatch.py --dry-run --sources customs_home # 单独验证海关总署是否可达
python riskwatch.py --test                          # 测企业微信通道（需 WECOM_WEBHOOK）
python riskwatch.py --mail-test                     # 测 QQ 邮箱（需三个邮件环境变量）
python riskwatch.py --report-test                   # 测群文件上传与消息
python riskwatch.py --once                          # 正式抓一次并投递（云端入口）
```

## 设计原则

- **零第三方依赖**：只用标准库。docx 由 `zipfile` 手写 OOXML 生成，云端不用装
  `python-docx` / LibreOffice / pandoc / 中文字体，runner 镜像升级也不会挂。
- **单源失败隔离**：某个源挂了照常出报告，并在「来源完整性」表里标红；
  **全部源失败**才发群告警并让任务变红（GitHub 会发通知邮件）。
- **双通道互不拖累**：邮件失败不影响企业微信，反之亦然；两者都失败才标红。
  群文件发不出去时，自动把报告核心章节分片发成消息兜底。
- **所有企业微信调用检查 `errcode`**：只看 HTTP 200 会漏掉业务失败。
- **密钥不出日志**：Webhook URL、SMTP 授权码、模型 key 均做脱敏；
  Secrets 只存在 GitHub，不进仓库、不贴聊天。
- **合规**：不抓微信公众号正文、不用 Cookie/抓包/模拟登录、不做 UI 自动化。
  官媒与香港海关的公众号内容改用同一机构官网、官方检索接口与香港政府官方 RSS 等同源渠道。

## 已知边界

- 风险等级、案件类型、类别与**专题维度**由**关键词规则**判定，是辅助线索而非官方定性，
  可能误判/漏判；专题关键词在 `riskwatch.py` 的 `LOCAL_GROUPS` 里，可按口岸业务口径调整。
- 人民日报 / 新华网 / 央视网条目是**报道线索**，不是监管机构正式通报；同题多源会标注
  「同题来源」，定性以官方原文为准。
- 各源设了 3–30 天不等的时间窗（按更新频率），窗内无新条目属正常，不是抓取失败。
  「走私」「旅检」等低频关键词近 7 天常无新稿，属正常。
- **海关总署首页有间歇性 412 风控**：本机实测时好时坏，GitHub 境外节点可能一直可达。
  长期失败就把 `customs_home` 从 `config.cloud.json` 的 `sources` 移除，不影响其他源。
- QQ 邮箱对**境外 IP** 的 SMTP 登录有风控，首次云端运行可能失败；指南排障表给了处置。
- 公开政府/媒体页面可能改版或临时不可达。解析器集中在 `riskwatch.py` 的
  `parse_*` 函数里，改一处即可；`--offline --dry-run` 可用本地样本回归。
